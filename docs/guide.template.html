开始之前

你只需要一个浏览器。这个页面由技术同事在放数据的那台服务器上启动，你用的是那台机器上的网页 —— 数据不会上传到任何地方，页面也不在互联网上。

你需要从技术同事那里拿到三样东西：

  • 地址，一般是 http://127.0.0.1:8765；
  • 怎么连上那台服务器 —— 远程桌面登录上去用它的浏览器，或者他帮你配好的隧道；
  • 数据放在服务器上哪个文件夹，例如 D:\quarantine\STUDY-001。

页面上的按钮和标签是英文的，本指南里照原样写出，例如 Read and propose。左边栏最下方有 使用指南 · Guide，随时能打开这份指南。

一次只能一个人用

两个人同时打开，后操作的人会覆盖前一个人的进度。约好轮流，一批做完再换人。

第一步：读数据，出建议01 · Read the drop

  1. 左边一列是五个步骤。当前这一步高亮；前一步做完，后一步才能点；做完的打 ✓。
  2. 数据所在的文件夹，填服务器上的路径。是文件夹不是文件：里面每个文件是一个域，文件名就是域名（LB.csv → LB）。能读 csv、xlsx、xpt、sas7bdat、parquet；老式 .xls 不行，先另存为 .xlsx。
  3. 原始 EDC 抽取就勾上 —— 列名里没有 DTC 结尾的列、日期写成 19/03/2025 这样的，就是原始抽取。勾上：日期按受试者整体偏移，原来的写法不变。不勾：日期变成"第几天"。拿不准就勾；忘了勾，下一屏会用黄框提醒你。
  4. 研究名，会写进合同和 manifest。不填就用文件夹名。
  5. k 目标，默认 5。没有特别要求就不改。
  6. 只在做"原始数据 → SDTM"训练对、而且两边受试者号写法不一样时才填。平时空着。
  7. 点它。数据越大越久，一般几秒到几十秒。

第二步：逐列确认02 · Review every column

这是整个流程里只有你能做的一步。工具对每一列提一个处理建议，你逐列点 OK（接受）或 Change（改掉）。

  1. 提示框，按颜色读：红＝不处理的话运行时一定会停；黄＝多半设置错了（比如该勾 raw 没勾）；蓝＝说明，看一眼就行。
  2. 进度：已决定几列、还剩几列空着。剩余归零之前进不了下一步。
  3. 批量按钮：把所有"HIGH 且还没决定"的行一次设成 OK。看下面的提醒再用。
  4. 把握程度：LOW / MEDIUM / HIGH。表格按它排序，工具最没把握的排在最上面 —— 你的注意力应该花在那里。旁边有 QUASI-ID 的列会计入重识别风险 k。
  5. 你的决定。还没决定的行底色是红的。

看一行的时候看什么

每一行从左到右是：Column（列名，下面灰字是域）、Proposed（工具打算怎么处理，下面是参数）、Why（为什么这么猜）、Decision（你的决定）。

问自己一个问题就够了：这一列里有没有能指向具体一个人的东西，工具的处理够不够？名字、编号、日期、地点、自由填写的备注，都要多看一眼。

改掉一条建议

  1. 点 Change，按钮变成棕色，下面展开三个框。框里已经预先填好了原来的建议，你只改你想改的那一处。
  2. 改成哪种处理，下拉选。截图里把 PKGRP 从 retain（原样保留）改成了 drop（整列删除）。
  3. 参数，多个用分号隔开，例如 entity=subject;prefix=SUBJ。drop 不需要参数，所以空着。
  4. 为什么改。会写进合同和 manifest，以后有人问"这一列当初为什么这么处理"，答案就是这一句。别空着。
  5. 点了 OK 的行：按钮变绿，红底消失。
  6. 还红着的行＝还没决定。

改了又后悔？直接点 OK，就回到接受原建议，刚才改的内容会被清掉。

受试者号那一行

  1. 受试者号会被换成随机的替代编号。这里通常带两个参数：
    preserve_format=True —— 替代编号保持原来的长度和格式：001-0042 → 394-9212。为了让数据看起来像真实数据，不影响保护强度。
    shape_prefix_from=SITEID —— 受试者号前几位本来就是中心号时，让替代编号的前几位跟中心的替代编号一致：受试者 002-0001 → 208-2262，中心 002 → 208。
  2. 理由里写着 site segment follows SITEID，就是第二个参数生效了。这两个一般直接 OK。

全部决定完

  1. 进度条满了，红字消失。
  2. 左边第三步 Sign it off 解锁了，点它。
关于那个批量按钮

Accept the N the profiler is confident about 只动 HIGH 且还没决定的行，MEDIUM 和 LOW 它不碰，那些必须一行一行看。

它省时间，但 HIGH 不等于对。点之前至少把每一行的 Why 扫一遍。签字的是你，不是工具。

第三步：签字03 · Sign it off

  1. 签字人：你本人的邮箱。不能是公共账号，不能空。
  2. 备注，可选，会跟签字一起记下。
  3. 合同存到哪，例如 D:\contracts\STUDY-001.yaml。一定要填：不填的话合同只存在于页面背后的内存里，服务器一重启就没了。
  4. 点它签字。还有空行的话会被拒绝，并列出是哪几列。
  5. 签好后显示签名（sha256:…）和保存位置。签名锁住的是这一整套规则：以后任何人改了合同文件里的任何一条，运行时都会被拒绝。把这个文件交给技术同事存档。

第四步：运行04 · Run

  1. 结果放到哪个文件夹。工具还会自动建一个同名加 _review 的文件夹，放需要人看、但不能交出去的东西。
  2. 金库文件，记着"真实编号 ↔ 替代编号"的对应关系。第一次会新建。同一个研究永远用同一个金库：换一个就等于换一套替代编号，前后两批数据再也对不上 —— 而且当时不会报错。
  3. 你的邮箱，记进 manifest。
  4. 格式：要用 Excel 打开就选 xlsx（默认，每一格按文本存，Excel 不会吃掉 002 的前导零）；进训练语料选 parquet；csv 给其他程序用，别用 Excel 打开再存回去。
  5. 开始运行。页面上没有密钥输入框，这是故意的 —— 密钥由启动控制台的人在服务器上设好。

第五步：看结果05 · Results

  1. 运行摘要：多少行、多少列、多少行待裁定，以及风险报告。下半段 smallest classes 列出的是最容易被认出来的几组人的特征组合 —— 别在屏幕共享、投屏时停在这一页。
  2. k 的结论：绿＝达标，红＝没达标。k 的意思是"最少有几个人长得一样"。先看它算了哪些列：如果只有中心、国家这种列，k 再高也只说明每个中心有很多行，不说明找到一个人有多难。没达标时摘要里会给出"再去掉哪些列能达标"的路径 —— 那是代价清单，不是建议，拿去跟负责人商量。
  3. 写出了哪些文件。…\STUDY-001-Q3.xlsx::LB 的意思是"这个 Excel 文件里名叫 LB 的那张表"。manifest.json 记录了这批数据是怎么处理的，要跟数据一起交付。
  4. 有文本需要人判断（黄框）。如果这里是绿框 Nothing flagged for adjudication，说明没有，输出文件夹就是成品，这一批结束了。
  5. 在页面上显示那些待判断的行。显示的是原文，没有脱敏。
  6. 交付前的提醒：manifest 跟数据一起交；_review 文件夹看完就删。

第六步：裁定待审文本only when step 5 shows a yellow box

自由填写的文本（备注、不良事件描述）里可能夹着人名、医院名、日期。工具会把可疑的行挑出来，由人判断是不是个人信息。

看 MARKED_TEXT 那一列，可疑片段用 [[…]] 框出来了，前面写着工具以为它是什么（PERSON 是人名）。每一行问一个问题：这是不是能指向受试者本人的信息？

原文判断为什么
repeat requested by Dr. OkaforPASS 保留研究者的名字，不是受试者
patient's daughter Mary Hartley phoned about the resultREDACT 去掉受试者家属的名字，能反推到受试者
这一步现在还不在网页里

网页能显示队列，但填判断、出最终版还要用命令行。请技术同事协助，或者按下面自己做：

  1. 用 Excel 打开 …\STUDY-001-Q3_review\review_queue.csv。
  2. 在 verdict 列填 PASS 或 REDACT。已经预先填好的行是工具按规则判的，可以改。REDACT 的行，replacement 列预填了只涂掉可疑片段的版本，也可以改。
  3. 保存时选 CSV UTF-8。
  4. 在服务器上运行（技术同事知道怎么设密钥）： 
    .\.venv\Scripts\deidkit.exe adjudicate "D:\tiers\STUDY-001-Q3" `
    --queue "D:\tiers\STUDY-001-Q3_review\review_queue.csv" `
    -o "D:\tiers\STUDY-001-Q3-final" --format xlsx `
    --operator 你的邮箱
  5. 出来的 …-final 文件夹才是成品。

它停下来的时候

工具会经常拒绝往下走。这不是坏了 —— 每一次都对应一件它不肯替你猜的事。页面顶部会出现红框：

  1. It stopped here，下面一句话说原因。截图里是文件夹名打错了一个字（STUDY-OO1，把数字 0 打成了字母 O）。改好再点一次就行。
红框里写着意思怎么办
… is not a folder on this server.路径不对检查拼写；确认填的是服务器上的路径，不是你自己电脑上的
N of M row(s) have no decision第二步还有空行回第二步，找红底的行
Who is approving?签字人没填填你的邮箱
DEIDKIT_VAULT_KEY is not set启动控制台时没设密钥找技术同事重启控制台。重启后从第一步重来，已保存的合同文件不受影响
the key supplied does not open …密钥和金库对不上找技术同事。不要换一个新金库绕过去
… value(s) were not shifted …有一列日期读不懂把红框文字发给技术同事
day/month order: unknown03/04/2025 是 3 月 4 日还是 4 月 3 日，数据自己说不清查数据传输规范；回第二步把这一列 Change，参数加 date_order=dmy（日/月/年）或 date_order=mdy（月/日/年）
… do not start with it"受试者号开头就是中心号"这个假设不成立回第二步把受试者那一列 Change，参数里删掉 shape_prefix_from=…
the shape of … admits only N value(s)这一列太短，没法保持原格式回第二步把这一列 Change，参数里删掉 preserve_format=True
… already published as another subject's surrogate新的真实编号撞上了以前发出去的替代编号极少见。找技术同事，不要换金库

关掉、刷新、重来

关掉浏览器、刷新页面都没关系。进度存在服务器那边，重新打开地址，页面会自己回到你上次停下的那一步。

在第二步已经做了决定之后，如果回到第一步又点了 Read and propose，它会先问你：

  1. Keep my decisions —— 不读了，回到你的审阅。点错了就点这个。
  2. Discard N decision(s) and read again —— 丢掉已经做的决定，重新读。只有数据文件真的换了才点这个。

会丢进度的只有一种情况：服务器上那个控制台被关掉或重启了。那样要从第一步重来 —— 已经保存的合同文件和已经输出的数据都不受影响。

常见问题

下一批数据来了，还要再逐列审一遍吗？
用网页的话，目前要。命令行可以把上一批签过字的决定带过来，只审新增或有变化的列 —— 请技术同事用 --carry-forward。
我点错了 OK 怎么办？
在签字之前，随时回第二步改。再点一次同一个按钮会取消，行变回红色。
签完字发现有一列处理错了？
回第二步改，再签一次。新的签名会覆盖旧的。已经用旧合同跑出来的数据要重新跑。
工具提议的我看不懂，能先全部 OK 吗？
技术上能，但签字的人是你。看不懂的那一列，把 Why 下面的说明和列名发给技术同事问 —— 那里面只有列名和处理方式，没有受试者数据。
结果文件夹里的东西可以直接发给别人吗？
可以发的是：数据文件 + manifest.json（有裁定时是 -final 文件夹里的）。不能发的：_review 文件夹、金库文件、合同以外的任何中间文件。
我能截图问问题吗？
第一到第四步的截图可以。第五步的运行摘要和待裁定队列不要截图外传 —— 前者有最容易被认出的人的特征组合，后者是没有脱敏的原文。

网页里还没有的

下面这些现在只能用命令行，找技术同事：

  • 裁定待审文本（第六步的 PASS / REDACT）；
  • 复用上一批的决定；
  • 反查某个替代编号对应的真实受试者，比如写严重不良事件报告时 —— 这个是故意只放在命令行里的，每一次都要写理由，并留下记录；
  • 多人同时使用。

更完整的背景 —— 为什么这样设计、每种处理方式的代价、交付和销毁的清单 —— 在同一文件夹下的 docs/manual.html。

本指南的截图全部来自编造的示例数据，里面没有真实的受试者、研究者或机构。真实数据、待裁定队列、_review 文件夹里的东西，都留在服务器上。
