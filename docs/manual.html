deidkit 怎么用

把外部送来的 EDC / SDTM 数据脱敏成可以分析、也可以作为训练材料的版本。日常操作在一个网页上完成：读数据、逐列确认、签字、运行、看结果。

先理解一件事

这个工具不替你做决定。它读你的数据，给每一列提一个处置建议，然后停下来等你确认 —— 确认过的东西才会执行，执行过的东西会留下证据。

谁做什么
工具识别每一列是什么，提议怎么处理，把不确定的排在最前面
你在网页上逐列点 OK 或改掉，然后签字
工具照你签的字执行，并在 manifest 里记下谁批准的、做了什么、风险多少
为什么要这么麻烦

工具的建议来自命名习惯和内容特征 —— 它不理解你的研究。AETERM 里那个人名是研究者还是受试者的女儿，只有人知道。所以没签字的合同一律不执行，网页上也绕不过去。

装一次就够

这一步找懂技术的人做，每台服务器一次。装在放数据的那台服务器上 —— 工具读的是那台机器硬盘上的文件，数据不需要、也不应该拷到别处。

git clone https://github.com/18007137528xl-spec/Data-Masking.git
cd Data-Masking
setup.bat

setup.bat 会建好环境、装依赖、用一份完全编造的合成研究跑一遍全流程，并检查输出是否满足设计承诺。看到 Setup complete and verified 就成了。

确认这个版本带网页控制台：

.\.venv\Scripts\deidkit.exe serve --help

能打出帮助就有。报 invalid choice: 'serve' 说明代码是旧的，让技术同事更新。

生产环境必须改一件事

setup 生成的 out\dev-vault.key 就放在它所打开的金库旁边。合成数据可以，真实数据绝对不行。真实数据的密钥要来自 KMS/HSM，而且能读数据层的账号不许能读密钥。这是技术同事的事，但你需要知道它没做完就不能上真实数据。

打开控制台

控制台是一个只在那台服务器上运行的网页。它不在互联网上 —— 浏览器和工具在同一台机器里对话，数据包连网卡都不经过。

在服务器上启动

最简单：在 Data-Masking 文件夹里双击 serve.bat。会弹出一个黑色窗口，稍等一下浏览器会自己打开控制台。它会自动找密钥：服务器上已经配置了密钥就用配置的；没有就用 setup 生成的开发密钥，并在窗口里提示你这是开发密钥。

不用双击的话，在 PowerShell 里三行，效果一样：

cd $HOME\Data-Masking
$env:DEIDKIT_VAULT_KEY = (Get-Content out\dev-vault.key -Raw).Trim()
.\.venv\Scripts\deidkit.exe serve --open

看到这个就启动好了：

deidkit console on http://127.0.0.1:8765
  the vault key is read from this process's environment, not the browser
  Ctrl-C to stop

在同一台机器上开浏览器，访问 http://127.0.0.1:8765。左边栏最下方的 User guide 是逐屏带截图的操作指南（英文），交给审阅的同事看那一份就够了。

这个窗口一直开着

这个窗口（双击 serve.bat 弹出来的黑窗口也一样）就是控制台本身。关掉它网页就打不开了；要停就在里面按 Ctrl+C。提示 The console may already be running in another window，多半是已经开着一个了 —— 找找另一个黑窗口，或者直接在浏览器打开 http://127.0.0.1:8765。确实要再开一个，换个端口：serve.bat --port 8766。

为什么密钥在这里设，不在网页上填

网页上故意没有密钥输入框。在浏览器里输入的密钥会进请求日志、浏览器的自动填充、以及任何一次屏幕共享。所以密钥只从启动它的那个窗口的环境里读 —— 第二行就是干这个的，漏了它，前三步都能走，到运行那一步会停下来。

从另一台电脑用

控制台只接受来自服务器本机的访问。同事要在自己电脑上用，两种办法：

  • 远程桌面登上服务器，用服务器上的浏览器开 http://127.0.0.1:8765。最简单。
  • SSH 隧道。在他自己电脑上运行 ssh -L 8765:127.0.0.1:8765 他的账号@服务器地址，然后在他自己的浏览器开同一个地址。

两种办法都要求他本来就有那台服务器的登录账号。这是有意的：控制台自己没有密码，能不能用它，由服务器的登录权限决定。

不要改成对外开放

启动命令有个 --host 参数，不要把它改成 0.0.0.0。那等于把一个不需要密码、还会显示未脱敏原文的页面挂到内网上 —— 比原来在 Excel 里填表的流程更危险。确实需要多人从网络访问，那是一个要配 TLS 和登录认证的部署项目，找技术同事。

一次只能一个人用

控制台现在是单人的。两个人同时开着页面，后读数据的那个会覆盖前一个的进度，前一个再点签字，签的是别人的数据。约好轮流，一个人做完一批再换人。

每一批数据走五步

控制台左边一列就是这五步。每一步做完，下一步才解锁；做完的步骤后面会标 done。按钮和标签是英文的，下面照原样写出。

01

读数据，出建议Read the drop · 只读，不改原始数据

Folder on this server 填数据所在的文件夹路径，例如 D:\quarantine\STUDY-001。注意是服务器上的路径 —— 从自己电脑连过来的同事最容易填成自己电脑上的。

文件夹里每个能读的文件是一个域，文件名就是域名：ae.csv → AE，dm.xpt → DM。能读 .csv .tsv .txt .parquet .xpt .sas7bdat .xlsx .xlsm；一个 Excel 工作簿里每个 sheet 一个域也行。.xls 老格式不行，另存为 .xlsx。

This is a raw EDC extract 这个勾，什么时候勾：

数据是勾不勾日期会变成
SDTM（有 AESTDTC 这类 DTC 结尾的列）不勾研究日（第几天）
原始 EDC 抽取（LBDAT、VISIT_DT、19/03/2025 这种）勾按受试者整体偏移，原写法不变

忘了勾也不怕：数据里一个 DTC 结尾的列都没有时，下一页会用黄色提示你。

Study / source name 不填就用文件夹名。k target 默认 5。Offset key template 只在做 raw→SDTM 训练对、两侧受试者号写法不同时才填，其余时候空着。

点 Read and propose。

02

逐列确认Review every column · 这一步只有你能做

页面顶上可能先出几条提示，按颜色读：

  • This will stop the run —— 不改的话第 4 步一定会停。先处理它。
  • Worth checking before you go on —— 大概率是设置错了，比如该勾 raw 没勾。
  • Note —— 说明，读一眼就行。

下面是表：一列数据一行，工具最没把握的排在最前面。每行四栏：

栏是什么
Column列名，下面灰字是它所在的域
Proposed工具准备怎么处理，下面是参数
Why把握程度：LOW / MEDIUM / HIGH。带 QUASI-ID 的列会计入重识别风险（k）。下面是它为什么这么猜
Decision你的决定

每一行点 OK（接受）或 Change（改掉）。还没决定的行底色是红的，顶上实时显示还有几行空着。一行空着就进不了第 3 步。

点 Change 会展开三个框，已经预先填好了原来的提议，你只需要改你想改的那一处：处置方式（下拉）、参数（用分号隔开，如 entity=subject;prefix=SUBJ）、你的理由。理由会写进合同和 manifest —— 以后有人问"为什么这一列这么处理"，答案就是它。

那个批量按钮

顶上有一个 Accept the N the profiler is confident about，一次把所有 HIGH 且还没决定的行设成 OK。MEDIUM 和 LOW 它不碰，那些必须逐行看。

它省时间，但 HIGH 不等于对。点之前至少把每一行的 Why 扫一眼。这个按钮就是"在 Excel 里把 decision 整列拖成 OK"的正式版 —— 区别只在于它被记录下来了。

你会在参数里看到的两个新东西

preserve_format=True —— 替身保持原值的长度和排版：数字还是数字，字母还是字母，分隔符照抄。

原值001-0042替身394-9212

这是为了训练语料看起来像真实数据 —— 生产里受试者号长成 001-0042，语料里就不该长成 SUBJ-3D7M2YVY。它不增加、也不减少保护：值照样是随机的、照样进金库、照样可逆。工具只在这一列"空间够大"时才提议（两位数的中心号这种窄编码不提议，因为抽着抽着会撞上真实编号）；中心名称永远不提议，因为保形会泄露每家医院名字的长度和结构。

shape_prefix_from=SITEID —— 受试者号里嵌着中心号时，让替身的前缀跟中心的替身对上。

原值SUBJECT 002-0001 SITEID 002替身SUBJECT 208-2262 SITEID 208

同一个中心的受试者共享前缀，不同中心不同 —— 原数据里"受试者号前三位就是中心"这个关系，在输出里依然成立。只有当数据里每一行都满足这个关系时工具才会提议。

这两个一般直接 OK。要关掉：点 Change，在参数框里把那一项删掉。

03

签字Sign it off · 审好的表变成带签名的合同

Approved by 填你本人，例如 你的邮箱@tigermedgrp.com。不能是服务账号，也不能空着。

Note 可选，会跟签字一起记下。

Write the approved contract to 填一个文件路径，例如 D:\contracts\STUDY-001.yaml。一定要填：不填的话合同只存在于控制台的内存里，服务器一重启就没了，下一批数据也没法复用。

点 Approve these rules。成功会显示一个 signature sha256:…。

这个签名是重点

签的是那一套具体规则，不是这个文件。批准之后任何人改动任何一条规则，签名就对不上，这份合同在所有地方都会拒绝使用。所以那个 .yaml 要交给技术同事提交进版本库 —— 它是这个研究的正式产物。

04

运行Run · 出脱敏后的数据

Output folder：结果放哪，例如 D:\tiers\STUDY-001-Q3。

Vault file：金库文件，例如 D:\vault\STUDY-001.db。第一次会新建。

同一个研究，永远同一个金库

金库记着"真实编号 → 替身"的对应。第二批数据指向同一个金库，同一个受试者才会拿到同一个替身，两批数据才拼得起来。换一个金库就是换一套替身，而且当时不会有任何报错 —— 两批数据看着都对，只是再也连不上了。

Operator：你的邮箱。

Format：

  • xlsx（默认）—— 要在 Excel 里打开看，选这个。每个单元格存为文本，Excel 不会把 002 吃掉前导零、不会把 2015-03 变成日期。
  • csv —— 给别的程序读。不要拿 Excel 直接打开它再存回去。
  • parquet —— 进训练语料用这个。

点 Run。出问题时页面顶部会出现红框 It stopped here，下面写着原因，对照它停下来的时候。

05

看结果Results · 决定是结束还是要裁定

最上面是运行摘要。接着是一个 k 的框：绿色是达标，红色是没达标。

读 k 之前看一眼它算的是什么

框里会列出计入的准标识符。如果只有 SITEID、COUNTRY 这种中心层面的列，那 k = 97 的意思只是"每个中心至少 97 行"，不代表找到一个具体的人有多难。年龄、性别、种族这些在别的表里、以后要一起发布的话，合起来的 k 才是要看的数，而且会低得多。

然后分两种情况：

绿框：Nothing flagged for adjudication

自由文本一行都没被标记。输出文件夹就是成品，这一批做完了。直接看交付与销毁。

黄框：N row(s) flagged for adjudication

有些自由文本行可能含 PHI，需要人判断。框里写着 review_queue.csv 的位置。

Show the queue on this screen 会把这些行直接显示在页面上。这时你屏幕上是未脱敏的原文 —— 别在屏幕共享、投屏的时候点。

裁定这一步现在还不在网页里

网页能显示队列，但填裁定、出最终版这一步还要用命令行。找技术同事，或者照下面自己做。

用 Excel 打开 review_queue.csv。只有 verdict 空白的行需要你 —— 其余的工具已按策略预填并注明来源，你可以推翻。

你填意思
PASS不是 PHI，原样发布
REDACT去掉。replacement 列已预填成只涂掉检出片段的版本，可以改

看 marked_text 列，可疑片段用 [[…]] 标出来了。典型的判断题：那个人名是研究者（可留）还是受试者亲属（必须去）？那家医院是研究中心（可留）还是他家附近那家（会把人缩到一个镇）？存回时选 CSV UTF-8。然后在服务器的 PowerShell 里（另开一个窗口，先设密钥）：

.\.venv\Scripts\deidkit.exe adjudicate "D:\tiers\STUDY-001-Q3" `
    --queue "D:\tiers\STUDY-001-Q3_review\review_queue.csv" `
    -o "D:\tiers\STUDY-001-Q3-final" `
    --format xlsx `
    --operator 你的邮箱@tigermedgrp.com

出来的 -final 文件夹才是成品。

为什么必须是两次：第 2 步说的是"AETERM 这一列走自由文本筛查"，它说不出那 220 个单元格里各写了什么。MH/AE 是全数保留、不做整列涂黑的 —— 那么逐字文本剩下的唯一防线就是逐行人工裁定。

它停下来的时候

工具会拒绝执行，而且拒绝得比较频繁。这不是坏了 —— 每一次拒绝都对应一件它不肯替你猜的事。网页上是顶部的红框 It stopped here，下面是原因。

12 of 83 row(s) have no decision ({'low': 9, 'medium': 3}).

第 2 步还有空行。一行空白就是一列没人形成过判断 —— 一份覆盖了它的批准会让 manifest 说假话。它会把没填的行列出来。

Who is approving? This is recorded in the contract and the manifest…

签字人空着。填你本人。

D:\quarantine\STUDY-001 is not a folder on this server.

路径不对，或者填了你自己电脑上的路径。控制台读的是服务器的硬盘。远程桌面或隧道过来的人最容易踩。

DEIDKIT_VAULT_KEY is not set

启动控制台的那个窗口没设密钥。在那个窗口按 Ctrl+C 停掉，补上第二行，重新 serve。重启后控制台的进度会清空，从第 1 步重来 —— 已经写出去的合同 .yaml 不受影响。

the key supplied does not open D:\vault\STUDY-001.db. Refusing to continue:
proceeding would issue a second, disjoint surrogate space for the same subjects.

密钥和金库对不上。用的不是当初建这个金库的那把钥匙。不要为了跑通就换一个新金库 —— 那样同一批受试者会拿到另一套替身。找到正确的密钥。

2853 value(s) were not shifted and would be published as recorded
  formats seen : {'UNPARSED': 2853}

有一列日期它读不懂。读不懂的值会原样输出 —— 那就是真实日期留在了脱敏结果里，所以它拦停而不是警告。把报错里的样例值给技术同事看。

day/month order: unknown -- set date_order

03/04/2025 是 3 月 4 日还是 4 月 3 日，这一列的数据自己证明不了。猜错会把每个日期挪到错误的月份，而且看起来仍然像日期。查这个研究的数据传输规范，回到第 2 步把这一列 Change，参数里加上 date_order=dmy 或 date_order=mdy。

'001-0042' is already published as another subject's surrogate in entity 'subject'.

保形替身撞车了。这一批里新出现了一个真实编号，恰好等于之前某一批抽出去的替身 —— 继续的话两个人会共用一个编号。极少见，但一旦发生不能静默放过。找技术同事；不要换金库绕过去。

shape_prefix_from names 'SITEID', but 3 value(s) do not start with it
-- '0001-77' does not begin with '002'.

"受试者号前缀就是中心号"这个关系在数据里不成立。回到第 2 步把受试者那一列 Change，参数里删掉 shape_prefix_from=…。

the shape of '7' admits only 10 value(s), too few to draw a distinct surrogate…

这一列太窄，不能保形。回到第 2 步把这一列 Change，参数里删掉 preserve_format=True。

this contract was edited after it was approved.
  approved : sha256:2bf4c051...    now : sha256:cf05da8a...

有人在批准之后改了合同文件。如果是你改的，重新走一次签字。如果不是你改的，那本身就是需要上报的发现。

不是拦停，但要你读的两类提示

blinding: LEAKED in N place(s)

药名或给药频率还留在某些列里，重标记碰不到那些地方 —— 比如 AE 叙述里写了"跳过下一次 Pembrolizumab"，或者 EXDOSFRQ 的 Q3W/Q6W 把两个组分得清清楚楚。自由文本那部分会在裁定时处理；剂量和频率要不要池化是个取舍（护住盲态 vs 保住暴露-反应分析），由你定。

k 没达标

k=1 意味着按准标识符组合看，几乎每个受试者都唯一。小样本试验必然如此 —— 120 例 × 7 个准标识符，组合空间远大于人数。工具会给出"再砍掉哪几个变量能达标"的路径，那是代价清单，不是建议：通常要砍掉年龄和种族，而那是大多数分析的分层变量。

这句话要记住

正确做法通常是把 k=1 作为已接受的残余风险写进 determination，并写明补偿控制（数据使用协议、访问控制、不外传、金库分离）。因为 —— 已接受的风险和未处理的疏漏，在数据里长得一模一样。区别只存在于你的文档里。

Change 能填什么

下拉框里的 16 种处置就是全部选项。必需参数是强制的 —— 缺了会被点名拒绝，填了工具不接受的参数也会。

处置做什么必需参数分析代价
retain原样发布—无
drop整列删除—全丢，除非 redundant_with 点名幸存列
surrogate_id随机替身 + 金库台账entity无；关联和可逆性都保住
faker换成一个像样的假值faker_provider原值不可恢复 —— 金库里什么都不写
date_to_study_day日期 → 相对锚点的天数—区间无损；日历没了，--DTC 也没了
partial_date_to_year_offset部分日期 → 相对年 + 粒度标记—低；绝不补天
dob_to_age出生日期 → 年龄，封顶—（cap 默认 90）低
date_shift保留 ISO 日期，按受试者偏移entity近似；SDTM 仍合规
date_shift_raw同样偏移，保留原始书写格式entity近似；给 raw→SDTM 训练对
cap_numeric封顶以下精确，以上并成一档cap低；只有尾部丢精度
generalize_numeric数值分档bins中；每个值都丢精度
zip3截成 3 位邮编，低人口前缀 → 000—低
pool_rare低频类别 → 池化值min_count整体轻，稀有类别全丢 —— 别用在 MH/AE
label_map不同值 → TRT A/TRT B，可逆entity分析上无；这是盲态，不是隐私
screen_freetext检出候选进队列，数据不改—无 —— 保护来自裁定，不是这条规则
redact_freetext就地检出并替换—高；会毁掉监管审阅需要的内容

参数的写法

参数框里多个参数用分号隔开，例如 entity=subject;preserve_format=true;shape_prefix_from=SITEID。

entity=subject             用哪个替身命名空间（subject / site …）
prefix=SUBJ                不保形时替身的前缀：SUBJ-XXXXXXXX
preserve_format=true       替身保持原值长度和排版
shape_prefix_from=SITEID   替身前缀跟着这一列的替身走
cap=90                     90 及以上并成一档
bins=0,18,40,65,90         generalize_numeric 的档位边界
min_count=5                pool_rare 阈值
keep_values=Placebo        label_map：这些值原样透传
date_order=dmy             date_shift_raw：03/04/2025 是 4 月 3 日
redundant_with=AESTDY      drop：内容幸存在哪一列
is_quasi_identifier=true   把这列计入 k
你改不动的部分

建议可以覆写，不变量不行。两条规则写同一个输出列、声称 de-identified 却保留真实日期、在全数保留的域（MH/AE）里做毁值处置、在组合编号模板里引用一个被删掉的列 —— 这些不论谁要求都会被拒绝，因为它们就是这个数据层的定义本身。

工具管不了的事

一、determination 文档。k=1 是已接受风险及其补偿控制、药名保留是明确决定、剂量频率保留的取舍 —— 这些必须有人写成文字。工具能证明做了什么，证明不了那是深思熟虑的结果。

二、拦不住没看就点 OK。工具能保证空白必须处理、批准留痕、签名绑定、最该想的排在最前 —— 但保证不了那些行被想过。批量按钮让这件事更快，不让它更对。

三、谁能坐在那台服务器前面。控制台自己没有密码，它的安全边界就是服务器的登录权限。谁能登上那台机器，谁就能打开它、看到待裁定队列里的原文。

四、HIPAA 以外的法规。这套工具是按美国 HIPAA / Expert Determination 建的。中国站点的受试者数据受 PIPL 管，尤其是作为训练材料和任何跨境传输 —— deidentified 这个标签的法律含义是 HIPAA 的，不自动等于 PIPL 下的"匿名化"。
