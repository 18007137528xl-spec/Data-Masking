操作手册 · 数据管理

deidkit 怎么用

把外部送来的 EDC / SDTM 数据脱敏成可以分析、也可以作为训练材料的版本。全程不需要写代码 —— 是几条命令,加一张你在 Excel 里填的表。

面向:数据管理 / 数据管理员 不需要编程基础 US HIPAA · Expert Determination

先理解一件事

这个工具不替你做决定。它读你的数据,给每一列提一个处置建议,然后停下来等你确认 —— 确认过的东西才会执行,执行过的东西会留下证据。

三个角色分得很清楚:

谁做什么
工具识别每一列是什么,提议怎么处理,把不确定的排在最前面
你在一张 Excel 表里逐行确认或改掉,然后签字
工具照你签的字执行,并在 manifest 里记下谁批准的、做了什么、风险多少
为什么要这么麻烦

工具的建议来自 SDTM 命名习惯和内容特征 —— 它不理解你的研究。AETERM 里那个人名是研究者还是受试者的女儿,只有人知道。所以未经确认的合同,run 会直接拒绝执行。

装一次就够

这一步找懂技术的人做,每台服务器一次。装完之后你不用再碰它。

git clone https://github.com/18007137528xl-spec/Data-Masking.git
cd Data-Masking
setup.bat

setup.bat 会建好环境、装依赖、用一份完全编造的合成研究跑一遍全流程,并检查输出是否满足设计承诺。看到 Setup complete and verified 就成了。

生产环境必须改一件事

setup 生成的 out\dev-vault.key 就放在它所打开的 vault 旁边。合成数据可以,真实数据绝对不行。真实数据的密钥要来自 KMS/HSM,而且能读数据层的账号不许能读密钥。这一步是技术同事的事,但你需要知道它没做完就不能上真实数据。

每一批数据走五步

下面每一步都在 PowerShell 里做,目录先切到 Data-Masking。命令里的路径换成你自己的。

00

开工前:给这个窗口设密钥每开一个新的 PowerShell 窗口都要设一次

cd $HOME\Data-Masking
$env:DEIDKIT_VAULT_KEY = (Get-Content out\dev-vault.key -Raw).Trim()

这是最容易漏的一步。环境变量只在当前窗口有效,关掉窗口就没了 —— 后面报"没有 vault key"基本都是漏了这一行。

01

看数据,出建议profile · 只读,不改你的原始数据

.\.venv\Scripts\python.exe -m deidkit.cli profile "D:\quarantine\STUDY-001" `
    -o STUDY-001.draft.yaml `
    --decisions STUDY-001_plan.csv `
    --blind-treatment

第一个参数是文件夹,不是单个文件。文件夹里每个能读的文件是一个域,文件名就是域名 —— ae.csv → AE,dm.xpt → DM。SDTM 的识别规则挂在这个名字上。

能读:.csv .tsv .txt .parquet .xpt .sas7bdat .xlsx .xlsm。一个 Excel 工作簿里每个 sheet 一个域也可以。.xls(2007 前的老格式)不行,用 Excel 另存为 .xlsx。

出两个文件:一份草稿合同(机器的建议,还不能用),和一份决策表 —— 那才是给你的。

常用开关

--blind-treatment 把药名换成 TRT A / TRT B,可逆。
--raw 数据是 raw EDC 而不是 SDTM 时加上 —— 日期靠值识别,不靠 --DTC 这种后缀。
--sdtm 交付物必须是合规 SDTM 时加上,--DTC 会被偏移但仍是合法 ISO 日期。

02

填决策表在 Excel 里做 · 这一步只有你能做

打开 STUDY-001_plan.csv。一列数据一行,工具最没把握的排在最前面 —— 83 条规则不需要平均用力。

列谁写是什么
proposed_treatment工具它准备怎么做
proposed_params工具用什么参数,如 cap=90
confidence · why · detail工具有多确定、依据是什么
decision你OK 接受 · CHANGE 改掉 · 留空 = 没看,会拦住整个运行
decision_treatment你填 CHANGE 时:改成哪一种处置
decision_params你如 cap=90、min_count=5
steward_note你你的理由 —— 会写进规则和 manifest
存回去的时候注意

Excel 的"另存为"默认会存成 .xlsx。这张表必须还是 CSV(选 CSV UTF-8),否则下一步读不到。

不确定 CHANGE 能填什么,随时查:

.\.venv\Scripts\python.exe -m deidkit.cli treatments
03

签字approve · 表变成带签名的合同

.\.venv\Scripts\python.exe -m deidkit.cli approve STUDY-001_plan.csv `
    -c STUDY-001.draft.yaml `
    --data "D:\quarantine\STUDY-001" `
    -o STUDY-001.yaml `
    --approved-by 你的邮箱@tigermedgrp.com

成功会回给你:

approved by  : 你的邮箱@tigermedgrp.com
decisions    : 79 accepted as proposed, 4 changed  (of 83)
fingerprint  : sha256:aacf7f0c975a5014...
这个指纹是重点

签的是那一套具体规则,不是这个文件。批准之后任何人改动任何一条规则,指纹就不匹配,合同在所有命令里都会拒绝加载。所以 STUDY-001.yaml 要提交进版本库 —— 它是你这个研究的正式产物,以后每批数据复用它,不用再走一次表。

04

执行run · 出脱敏后的数据

.\.venv\Scripts\python.exe -m deidkit.cli run "D:\quarantine\STUDY-001" `
    -c STUDY-001.yaml `
    -o "D:\tiers\STUDY-001-Q3" `
    --vault "D:\vault\STUDY-001.db" `
    --format xlsx `
    --operator 你的邮箱@tigermedgrp.com

--format 可以是 xlsx、csv 或 parquet。

建议用 xlsx

不是为了方便。一个 CSV 的输出在 Excel 里打开,等于让 Excel 重新解释一遍:2015-03 变日期、中心号 002 掉前导零、长受试者编号变科学计数。脱敏活得下来,数据活不下来。--format xlsx 把每个单元格存为文本,Excel 就不再猜了。

产出两个位置 —— 一个给分析,一个不给:

D:\tiers\STUDY-001-Q3\           脱敏后的数据 + manifest.json
D:\tiers\STUDY-001-Q3_review\    review_queue.csv + risk_detail.json

_review 那个目录里是原始未脱敏的文本和最容易被重识别的那些受试者的准标识符组合。它要按 vault 的权限管,不是按分析员的权限管,而且裁定完就删。

05

裁定自由文本,出最终版adjudicate · 这一步的产物才是能交出去的

打开 review_queue.csv。只有 verdict 空白的行需要你 —— 其余的工具已经按策略预填并注明了来源,你可以推翻。

你填意思
PASS这不是 PHI,原样发布
REDACT去掉。replacement 列已经预填成只涂掉检出片段的版本,你可以改

看 marked_text 列,可疑片段已经用 [[…]] 标出来了。典型的判断题:那个人名是研究者(可留)还是受试者亲属(必须去)?那家医院是研究中心(可留)还是他家附近那家(会把人缩到一个镇)?

.\.venv\Scripts\python.exe -m deidkit.cli adjudicate "D:\tiers\STUDY-001-Q3" `
    --queue "D:\tiers\STUDY-001-Q3_review\review_queue.csv" `
    --out "D:\tiers\STUDY-001-Q3-final" `
    --operator 你的邮箱@tigermedgrp.com
交付

-final 那个目录才是能交出去的。它的 manifest 里会写清楚谁裁定的、涂掉几行、放行几行、有没有留下缺口。交付完把整个 _review 目录删掉。

为什么必须是两次:决策表说的是"AETERM 这一列走自由文本筛查",它说不出那 220 个单元格里各写了什么。而 MH/AE 是全数保留、不做整列涂黑的 —— 那么逐字文本剩下的唯一防线就是逐行人工裁定。

它停下来的时候

工具会拒绝执行,而且拒绝得比较频繁。这不是坏了 —— 每一次拒绝都对应一件它不肯替你猜的事。下面是你会遇到的几种,以及各自的意思。

error: STUDY-001.draft.yaml has not been approved.

你拿草稿去跑了。草稿是机器的猜测。回到第 2 步填表,第 3 步 approve,然后用它输出的那个 .yaml。

error: 12 of 83 row(s) have no decision ({'low': 9, 'medium': 3}).

决策表还有空行。一行空白就是一列没人形成过判断 —— 一份覆盖了它的批准会让 manifest 说假话。它会把没填的行列出来给你。

error: cannot write out\plan.csv -- it is locked by another program.
On Windows that is almost always Excel holding the file open.

表还开在 Excel 里。关掉再跑。它是在做任何事之前检查的,所以什么都没被改动。

error: 2853 value(s) were not shifted and would be published as recorded
  formats seen : {'UNPARSED': 2853}

有一列日期它读不懂。读不懂的值会原样输出 —— 那就是真实日期留在了脱敏结果里,所以它拦停而不是警告。把报错里的样例值贴给技术同事看。

error: day/month order: unknown -- set date_order

03/04/2025 是 3 月 4 日还是 4 月 3 日,这一列的数据自己证明不了。猜错会把每个日期挪到错误的月份,而且看起来仍然像日期。查一下这个研究的数据传输规范,在决策表里填 date_order=dmy 或 date_order=mdy。

error: 16 row(s) have no verdict.

自由文本队列没填完。没裁定的行会原样发布,而这些行是被标记为"可能含 PHI"的 —— 这是最后一道关。填完,或者用 --allow-pending 明确放行(manifest 会记下这个缺口)。

error: this contract was edited after it was approved.
  approved : sha256:2bf4c051...    now : sha256:cf05da8a...

有人在批准之后改了合同。如果是你改的,重新走一次 approve。如果不是你改的,那本身就是需要上报的发现。

不是拦停,但要你读的两类提示

blinding: LEAKED in N place(s)

药名或给药频率还留在某些列里,重标记碰不到那些地方 —— 比如 AE 叙述里写了"跳过下一次 Pembrolizumab",或者 EXDOSFRQ 的 Q3W/Q6W 把两个组分得清清楚楚。自由文本那部分会在第 5 步裁定;剂量和频率要不要池化是个取舍(护住盲态 vs 保住暴露-反应分析),由你定。

NOTE: the k target was not met

k=1 意味着按准标识符组合看,几乎每个受试者都唯一。小样本试验必然如此 —— 120 例 × 7 个准标识符,组合空间远大于人数。工具会给出一条"再砍掉哪几个变量能到 k=15"的路径,那是代价清单,不是建议:通常要砍掉年龄和种族,而那是大多数分析的分层变量。

这句话要记住

正确做法通常是把 k=1 作为已接受的残余风险写进 determination,并写明补偿控制(数据使用协议、访问控制、不外传、vault 分离)。因为 —— 已接受的风险和未处理的疏漏,在数据里长得一模一样。区别只存在于你的文档里。

决策表里能填什么

这 16 种是 decision_treatment 的全部选项。必需参数是强制的 —— 缺了会被点名拒绝,填了工具不接受的参数也会。

处置做什么必需参数分析代价
retain原样发布—无
drop整列删除—全丢,除非 redundant_with 点名幸存列
surrogate_id随机替身 + vault 台账entity无;join 和可逆性都保住
faker换成一个像样的假值faker_provider原值不可恢复 —— vault 里什么都不写
date_to_study_day日期 → 相对 anchor 的天数—区间无损;日历没了,--DTC 也没了
partial_date_to_year_offset部分日期 → 相对年 + 粒度标记—低;绝不补天
dob_to_age出生日期 → 年龄,封顶— (cap 默认 90)低
date_shift保留 ISO 日期,按受试者偏移entity近似;SDTM 仍合规
date_shift_raw同样偏移,保留原始书写格式entity近似;给 raw→SDTM 训练对
cap_numeric封顶以下精确,以上并成一档cap低;只有尾部丢精度
generalize_numeric数值分档bins中;每个值都丢精度
zip3截成 3 位邮编,低人口前缀 → 000—低
pool_rare低频类别 → 池化值min_count整体轻,稀有类别全丢 —— 别用在 MH/AE
label_map不同值 → TRT A/TRT B,可逆entity分析上无;这是盲态,不是隐私
screen_freetext检出候选进队列,数据不改—无 —— 保护来自第 5 步裁定,不是这条规则
redact_freetext就地检出并替换—高;会毁掉监管审阅需要的内容

decision_params 写法

cap=90                     90 及以上并成一档
bins=0,18,40,65,90         generalize_numeric 的档位边界
min_count=5                pool_rare 阈值
entity=subject             用哪个替身命名空间
keep_values=Placebo        label_map:这些值原样透传
date_order=dmy             date_shift_raw:03/04/2025 是 4 月 3 日
redundant_with=AESTDY      drop:内容幸存在哪一列
is_quasi_identifier=true   把这列计入 k 匿名度量
你改不动的部分

建议可以覆写,不变量不行。两条规则写同一个输出列、声称"de-identified"却保留真实日期、在"全数保留"的域(MH/AE)里做毁值处置 —— 这些不论谁要求都会被拒绝,因为它们就是这个 tier 的定义本身。

交付与销毁

文件怎么处理
STUDY-001-Q3-final\交出去的就是这个。数据 + manifest
STUDY-001.yaml提交进版本库。下一批数据复用,不必再填表
vault\STUDY-001.db加密的对照台账。安全报告要反查真人时用它。销毁它就是把假名化数据变成匿名数据 —— 一个需要按流程做的决定

需要反查真实受试者时

.\.venv\Scripts\python.exe -m deidkit.cli reverse SUBJ-7QK2XM4A `
    --entity subject --vault "D:\vault\STUDY-001.db" `
    -j "SAE-2026-0031 快速安全报告"

-j 是强制的理由,而且会写进访问日志 —— 通向真实标识符的路径只有这一条,而且没有不留痕的走法。查谁反查过什么:deidkit vault log。

工具管不了的三件事

一、determination 文档。k=1 是已接受风险及其补偿控制、药名保留是明确决定、剂量频率保留的取舍 —— 这些必须有人写成文字。工具能证明做了什么,证明不了那是深思熟虑的结果。

二、拦不住有人把 decision 整列拖成 OK。工具能保证空白必须处理、批准留痕、指纹绑定、最该想的排在最前 —— 但保证不了那些行被想过。approve 在一条改动都没有的时候会自己说出这句话。

三、HIPAA 以外的法规。这套工具是按美国 HIPAA / Expert Determination 建的。中国站点的受试者数据受 PIPL 管,尤其是作为训练材料和任何跨境传输 —— tier: deidentified 这个标签的法律含义是 HIPAA 的,不自动等于 PIPL 下的"匿名化"。

不确定某个报错的意思、或者觉得某一列的建议不对,把控制台输出或决策表贴出来问 —— 那里面只有列名和处置方式,没有受试者数据。真实 EDC 数据留在服务器上,不要传出去。
